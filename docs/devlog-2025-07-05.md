
### 1.2 前端 — GeoServer 管理面板

页面：`ol-backend-demo/03-geoserver-rest.vue`（路由：`/ol-backend-demo/geoserver-rest`）

**布局：** 地图 + 搜索框右侧管理按钮 + 下拉面板

**面板包含 4 个 Tab：**

-   **工作空间** — 列表 + 创建
-   **数据存储** — 列表 + 创建（PostGIS，默认连 localhost:5432/webgistest）
-   **要素类型** — 列表（需选工作空间+数据存储）
-   **图层** — 列表 + \[加载\]/\[移除\] + 发布

**图层加载：** 使用 WFS bbox 策略（VectorSource），不是 WMS 瓦片。原因：WMS 是图片，无矢量 feature，属性表查不到数据。

## 二、遇到的错误与解决方案

### 2.1 Vue `ref()` 深度代理导致 OL 对象引用失效

**现象：** 点击"移除"后 LayerControl 列表变空，但地图上图层仍在。

**原因：** 用 `ref<Map<string,any>>(new Map())` 存储 OL Layer 对象时，Vue 3 的 `ref()` 会对 Map 内存储的值做深度响应式代理。OL 的 `TileLayer`/`VectorLayer` 等类实例被代理后，`map.removeLayer()` 内部用 `===` 比对引用，代理对象 ≠ 原始对象，匹配失败，移除无效。

**解法：** 三条规则：

``` ts
// ❌ 错误 — Vue ref 会深度代理 OL 对象
const addedLayers = ref<Map<string, any>>(new Map())
const wmsLayer = new TileLayer(...)
addedLayers.value.set("xxx", wmsLayer) // 存入时被代理
// ...
m.removeLayer(addedLayers.value.get("xxx")) // 取出的是代理，≠ 原始引用

// ✅ 正确 — 三条规则
// 1. OL 对象用 markRaw() 标记，告诉 Vue "别碰它"
import { markRaw } from "vue"
const layer = markRaw(new VectorLayer(...))

// 2. 存储用 reactive Set（值类型）而非 ref Map（对象类型被代理）
const addedLayerNames = reactive(new Set<string>())

// 3. 地图容器 map 用 shallowRef 而非 ref
// shallowRef：只有 .value 赋值触发更新，.value 内部不做深度代理
const map = shallowRef<Map | null>(null)
```

### 2.2 GeoServer WMTS `style` 参数

**现象：** WMTS GetTile 请求返回 400 Bad Request。

**原因：** OGC WMTS 1.0.0 规范规定 `style` 是必填参数，OL 严格遵循，自动拼入 URL。但 GeoServer GWC 不接受 `style` 参数，接到就 400。这是 GeoServer 和 OGC 标准打架。

**解法：** 删掉 `style` 参数（JS 下不传，TS 下设 `style: ''`），让 OL 不拼这个参数。

### 2.3 GeoServer REST API 列表端点只返回 `name` + `href`

**现象：** 后端返回的 DataStore type、FeatureType nativeName、Layer type 全是 null。

**原因：** GeoServer REST API 的 summary 端点（如 `/workspaces/{ws}/datastores.json`）只返回 `{name, href}`。`type` 等详细字段在单个资源的 detail 端点（如 `/workspaces/{ws}/datastores/{ds}.json`）里才有。

**解法：** 两种方案：

-   A）先拿 summary 列表 → 对每个 item 并行调 detail 端点 → N+1 调用，数据完整
-   B）只用 summary 返回的 name，放弃其它字段

最终采用方案 B——列表只展示图层名，操作列加按钮足够。方案 A 的代码已写但后来被简化掉，放在文末附注。

### 2.4 GeoServer EPSG:4326 网格集名称

**现象：** WMTS 加载 4326 数据，matrixSet 写成 `EPSG:3857` 导致请求中网格集不存在。

**原因：** GeoServer GWC 中 Web Mercator 的网格集名叫 `EPSG:900913`（旧编号）不是 `EPSG:3857`。而 4326 数据的网格集叫 `EPSG:4326`。

**解法：** 需要先调 `GetCapabilities` 确认实际网格集名称，再填入 OL WMTS 构造参数。同时 `matrixIds` 必须使用完整格式（如 `EPSG:4326:0`），不能用纯数字。

### 2.5 WMS Tile 图层无属性数据

**现象：** 通过 WMS TileWMS 加载的图层，在 LayerControl 中点属性表显示"暂无数据"。

**原因：** WMS 是渲染成图片瓦片返回的，`TileWMS` source 没有 `getFeatures()` 方法。属性表需要 VectorSource 的 feature 集合才能工作。

**解法：** 改 WMS 为 WFS 加载。`VectorSource` + bbox 策略 + `GeoJSON` format → 矢量 feature 进属性表。同时保持 LayerControl 对无 `getFeatures()` 源的防御逻辑。
